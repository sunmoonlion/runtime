# Windows 代理下载与首次接入：一页待审方案

2026-10-09，Luna 提交 Fable 审读、所有者定案。**仅方案，尚未修改或发布功能。**

## 用户走一条路

**「我的机器」→ 下载 Windows 包 → 安装 → 领取接入令牌 → 本机初始化和选择目录 → 启动 → 网页看到在线。**
第一期面向 Windows x64；包内带官方 Node、固定 Codex 和 JS，无自制 exe、无 Python、无须另装运行时。
默认普通用户安装；管理员沙箱和登录自启由用户另选。网页不能替用户授权目录、网络或命令。

## 实现安排

| 环节 | 建议做法与失败处理 |
| --- | --- |
| 下载 | 「我的机器」显示版本、兼容的 Codex 版本、大小、ZIP SHA256、清单 SHA256 和安装说明。使用边缘站点固定版本的 HTTPS 静态路径，例如 `/downloads/agent/<release>/windows-x64.zip`（**拟定，未发布**）。只在包已上传并校验、兼容性核对后更新发布目录；没有可用包就明确显示暂不可下载。支持断点续传。安装包不含用户配置或令牌。 |
| 安装 | 保留当前完整包及 `install.cmd`，由页面给出适配 PowerShell 的校验、预览、安装命令。摘要取自可信发布记录；同包清单只证明文件完整，**不等于发布者签名**。开发环境须先配置信任的站点 CA，不能关 TLS 校验；系统应用控制拦截时给出诊断，不能自动绕过。正式对外发行前单独定签名与可信分发门槛。 |
| 首次令牌 | 复用现有登录、CSRF 和 `POST /api/workbench/sandboxes/provision`：已登记模型 key、容量允许，首次创建沙箱时返回本人 agent 令牌一次。将设置页现有这段接入 UI 提取复用到「我的机器」，避免两套签发逻辑；不因打开页面、下载或刷新而创建沙箱/签发令牌。只读状态接口始终不返回令牌。 |
| 本机接入 | 页面给出安装目录下 `sunmoon-agent.cmd init` 的命令，地址/用户由后端返回，目录在本机选。建议为 CLI 增加**隐藏输入令牌**的交互，网页单独提供一次性查看/复制，避免令牌写入命令行参数和 PowerShell 历史；这不是浏览器登录流程。沿用本机权限设置和默认禁网，网页不代选目录或放宽上限。 |
| 丢失、到期与替换 | 已有身份不重新展示旧令牌；用户明确点「重新领取并撤销旧令牌」才调用既有 rotate。先说明旧代理会断开、在跑沙箱可能滚动；禁止自动重试签发/轮换，响应丢失先查状态。页面刷新后敏感内容清空；到期/吊销在本机显示下一步。**当前一用户只允许一个在线代理**，连接另一台会替换原连接，页面须提前说明。 |
| 安全与维护 | 签发/轮换响应 `Cache-Control: no-store`；令牌只在页面短暂内存和本机私有配置，不进 URL、浏览器持久存储、日志、埋点或包。后端校验本人身份、Origin/CSRF，并限制重复操作；兼容登记沿用现有 relay 协议，不另建令牌体系。升级仍是校验新包→卸载保留配置→安装，不引入自动更新。 |

## 先定的三件事

1. **采用上述最小接入路径**：首次令牌仍随沙箱创建返回，需要先登记模型 key；暂不增加「没有沙箱也独立领令牌」或浏览器登录配对流程。
2. **有效期不能含糊**：现有 `tokens.py` 默认 **90 天**，与 `C-I9` 的“短期令牌”存在差距。建议本期 agent 令牌改为 **24 小时、明确显示到期时间、人工重新领取**；仅调整 agent 的签发参数，不顺带改其他令牌期限。若要求长期无人值守自启，需要先另定续期方案，不能把 90 天称为已符合短期约束。此项需所有者取舍；现有轮换仍会联动沙箱，不能隐瞒此影响。
3. **发布范围**：先做现有开发站点的固定版本下载和接入闭环；真人 GUI 允许、安装后网页在线、重启登录、可选 UAC、干净 Windows 尚待验，完成前不标成面向公众的正式发行。

## 批准后的顺序与验收

先后端契约/期限/防重复和保密 → CLI 隐藏输入 → 网页复用接入流程 → 固定源码组包、发布静态物料 → 实机从下载开始验收。
覆盖首次成功、刷新不换令牌、身份已存在、响应丢失、轮换旧令牌失效、到期/吊销、跨用户与 CSRF 拒绝、断网续传、坏摘要拒装；检查参数/日志/浏览器存储无令牌，并由所有者从已装版本看到在线。
下载失败与签发失败分别提示；回退发布目录可恢复旧兼容包，**不能恢复已吊销的令牌**。仍仅本地提交，由所有者同步；luna 合入前不从 fable 发布投资后端/relay。
